# 🧳 여행 추천 CLI 앱 (Gemini + Kakao)

날짜를 입력하면 **Gemini LLM**이 여행지를 추천하고, **카카오맵 Local API**로 맛집을 검색해
**여행 리포트(Markdown)** 를 자동 생성하는 CLI 프로그램입니다.

---

## 📌 프로그램 개요

- **입력**: `-date "YYYY-MM-DD"` (필수)
- **출력**: 진행 로그 + `results/` 폴더에 결과 파일 저장
- **핵심 흐름**:
  `날짜 입력 → LLM 추천(JSON) → 도시명 추출·정규화 → 맛집 검색(JSON) → 최종 리포트(MD)`

---

## 🏗️ 프로그램 구조 (모듈/함수 분리)

각 단계는 **책임별 함수로 분리**되어 있으며, 입력·출력 경계가 명확합니다.

| 함수 / 모듈 | 책임 | 입력 | 출력 |
|-------------|------|------|------|
| `parse_args()` | CLI 인자 파싱·검증 | `sys.argv` | `date: str` |
| `get_recommendation(date)` | LLM 여행지 추천 | `date: str` | `dict` (1차 JSON) |
| `normalize_city(city)` | 지명 표준화 | `city: str` | `city: str` (정규화) |
| `search_restaurants(city)` | 카카오 맛집 검색 | `city: str` | `list[dict]` |
| `build_report(rec, foods, errors)` | 리포트 생성 | JSON+리스트 | `md: str` |
| `save_results(date, raw, report)` | 파일 저장 | 데이터 | 저장 경로 |

> **경계 원칙**: 각 함수는 앞 단계의 출력(JSON/리스트)만 입력으로 받아
> 다음 단계로 넘기며, 실패해도 `errors`에 기록 후 흐름을 이어갑니다.

## 🔑 API 키 설정 방법

프로젝트 폴더에 `.env` 파일을 만들고 아래처럼 작성하세요.

GEMINI_API_KEY=발급받은_제미나이_키
KAKAO_API_KEY=발급받은_카카오_REST_API_키

- API 키는 **코드에 직접 작성하지 않습니다.**
- 코드에서는 `os.getenv("GEMINI_API_KEY")` 로 읽어옵니다.
- `.env` 는 `.gitignore` 에 등록되어 **GitHub에 올라가지 않습니다.**

## 📄 1차 추천 JSON 스키마

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `recommended_city` | string | ✅ | 추천 도시명 |
| `weather` | string | ✅ | 해당 시기 날씨 요약 |
| `events` | array of string | ✅ | 행사/축제 후보 1~3개 |
| `reason` | string | ✅ | 추천 근거 2~4문장 |

**예시**
{
  "recommended_city": "제주",
  "weather": "초여름, 대체로 맑고 온화함",
  "events": ["제주 수국 축제", "성산일출봉 여름 행사"],
  "reason": "6월 중순 만개하는 수국을 감상하기 좋습니다. 습도가 높지 않아 관광에 적합합니다."
}

### JSON 검증 절차
파싱 후 아래를 **순서대로 검사**합니다.
1. **필수 키 존재 확인**: 4개 키가 모두 있는지 검사
2. **타입 검사**:
   - `recommended_city`, `weather`, `reason` → `str` 인지
   - `events` → `list` 이며 원소가 모두 `str` 인지
3. 검사 실패 시 → **재시도 1회** (아래 파싱 정책 참고)

## 🗺️ 지도 API 연동 (카카오맵 Local)

추천 도시명을 입력으로 카카오맵에서 **맛집 5곳**을 검색합니다.

### 맛집 아이템 필드
| 필드 | 매핑(카카오) | 설명 |
|------|------|------|
| `place_name` | `place_name` | 상호명 |
| `address` | `road_address_name` | 주소 |
| `category` | `category_name` | 카테고리 |
| `url` | `place_url` | 상세 링크 |
| `x / y` | `x` / `y` | 좌표 |

### 지도 호출 성공/실패 흐름
검색 시도
 ├─ 성공(1건 이상) → 맛집 리스트 반환
 ├─ 성공(0건)      → "데이터 없음" 상태로 리포트 계속 진행
 └─ 실패(인증/네트워크/쿼터) → errors 기록 + "데이터 없음" 처리 후 계속 진행

## 🌐 REST API 개념 (GET vs POST)

| 메서드 | 용도 | 이 프로젝트 예시 | 권장 설정 |
|--------|------|------------------|-----------|
| **GET** | 데이터 **조회** | 카카오 맛집 검색 (쿼리 파라미터) | 헤더 `Authorization: KakaoAK {키}`, timeout=5s |
| **POST** | 데이터 **생성/전송** | Gemini에 프롬프트 본문 전송 | `Content-Type: application/json`, timeout=15s |

> LLM 출력을 **JSON으로 구조화**하여 다음 단계(장소 검색)의 입력으로 연결하는 것이 핵심 흐름입니다.

## 🚨 에러 처리 정책

| 상황 | 처리 |
|------|------|
| API 키 미설정 | 즉시 종료 + 설정 방법 안내 출력 |
| 지도 API 실패 | 맛집 "데이터 없음" 처리 후 리포트 계속 생성 |
| 검색 결과 0건 | 중단 없이 "데이터 없음" 상태로 진행 |
| LLM JSON 파싱 실패 | 재시도 1회 (필수 키만 다시 JSON 출력 요청) |

### LLM JSON 파싱 보정 규칙
파싱 실패 시 아래 우선순위로 **보정 후 재파싱**을 시도합니다.
1. 코드블록 마커 제거: ```json, ``` 제거
2. 앞뒤 설명 텍스트 제거: **첫 `{` ~ 마지막 `}` 구간만** 추출
3. 위 보정으로도 실패 시 → **재요청 1회**
   ("설명 없이 필수 키만 순수 JSON으로 출력하라"고 프롬프트 수정)

### 401 / 403 디버깅 체크리스트
인증 오류(401/403) 발생 시:
1. `.env` 의 **키 값 오타** 확인
2. 카카오: **REST API 키**인지 (JS 키 아님) 확인
3. **헤더명 오타** 확인 → `Authorization: KakaoAK {키}`
4. 카카오 개발자 콘솔에서 **Local API 권한 활성화** 여부 확인
5. 로그 확인: 응답 상태 코드와 본문을 아래 형식으로 출력해 점검
   [DEBUG] status=401 body={"errorType":"AccessDeniedError", ...}

### errors 항목 구조
발생한 오류는 내부 `errors` 리스트에 쌓여 **원본 JSON의 `errors` 섹션**에 요약됩니다.
"errors": [
  { "code": "MAP_API_FAIL", "message": "카카오 응답 401", "time": "2024-06-15T10:22:31" }
]

## ⚡ 캐싱 정책 (동일 날짜 재사용)

같은 날짜로 다시 실행하면 **불필요한 API 호출을 줄이기 위해** 캐시를 재사용합니다.

- **캐시 위치**: `results/raw_{날짜}.json`
- **캐시 판단**: 실행 시 해당 날짜의 raw JSON이 이미 있으면 **API 호출 없이 재사용**
- **캐시 우선순위**: 기존 raw JSON 존재 → 재사용 / 없으면 → 새로 API 호출
- **캐시 무효화**: `--no-cache` 옵션 사용 시 캐시 무시하고 새로 호출
  (예: `python main.py -date "2024-06-15" --no-cache`)

## 🏷️ 지명 정규화 (도시명 표준화)

LLM이 추천한 도시명을 **카카오 검색이 잘 되는 표준 지명**으로 보정합니다.

### 정규화 규칙
1. **공백/특수문자 제거**: `"제주 "` → `"제주"`
2. **접미사 정리**: `"제주도"` → `"제주"`, `"강릉시"` → `"강릉"`
3. **별칭 매핑 테이블** 적용:

| 입력(별칭) | 표준 지명 |
|-----------|-----------|
| 제주도 / 제주특별자치도 | 제주 |
| 강릉시 | 강릉 |
| 여수시 | 여수 |
| 서울특별시 | 서울 |
| 부산광역시 | 부산 |

> 표준화된 지명 + `"맛집"` 키워드로 검색 정확도를 높입니다.
> (예: `"제주 맛집"` 으로 카카오 Local API 호출)
